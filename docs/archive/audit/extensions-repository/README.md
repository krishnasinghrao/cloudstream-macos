# Reproducing the extension/repository audit

These are opt-in **characterization probes** for defects recorded in REPORT.md.
A passing probe means it reproduced the documented defect. They must not be
mistaken for tests demonstrating correct or secure behavior.

From the repository root:

```sh
./gradlew :macos:daemon:test --offline --console=plain --no-configuration-cache \
  -I macos/docs/audit/extensions-repository/audit.init.gradle \
  --tests com.lagradost.macos.ExtensionsRepositoryAuditProbe
```

The init script adds this directory as a test source only for the opted-in run.
It selects `macos/daemon/build/tmp/extensions-audit-home`, which each probe resets.
HTTP is intercepted; an unexpected network request fails the probe. No real
community extension is used. Lifecycle fixtures use a synthetic CS3 and warmed
JAR cache with a harmless test-classpath plugin; they do not test dex translation.
Do not run these global-singleton probes concurrently in the same JVM or against
a production data root.

Run the normal suite afterward to restore ordinary test outputs:

```sh
./gradlew :macos:daemon:test --offline --console=plain
```
